# brief 模板：独立事实核查 + 唱反调（独立 subagent，可和盲测并行）

> 用法：复制本文件，替换 `<…>`，整段发给一个**没参与写稿**的 subagent。核查和唱反调可以是同一个 agent 的两部分，也可以拆成两个。

你不是作者，不许改原稿。

核查对象：`<口播文件路径>` 的口播句（`- ` 开头的行）及文末「事实口径表」。原文 = `<论文 PDF / 网页路径；多来源时逐个列出>`。

## 一、逐句核查
- 每个数字：对不对、出处（页 / 图 / 表）、适用范围（benchmark、设置、k、跑几次）有没有说清。
- 归因强度：论文说「确定」还是「推测 / may account for」；口播有没有说重。
- 限定条件、比较对象：「最强」「最多」「第一」是否在所有评测都成立，没成立就说「平均」或点名评测。
- 「推测」「我猜」是否标明；设计意图有没有被说成已证实的结果。
- 分组是否和论文原表一致；术语前后是否一个叫法。
- 有没有把一个设置下的结论说成普遍；有没有无证据地说「最近很火」；旧内容是否被标成「最新」。
- 找不到出处的说法一律 must-fix（删或改）。
- 额外硬规则：口播不用「不是……而是……」；不预告下一期；结尾是讨论问题 + 署名配置；`<作者自己的其他禁区>`。

## 二、唱反调（只看论文，站审稿人立场）
- 最脆弱的假设是什么？反例怎么设计？
- 对比是否公平（预算、k、基线有没有调好）？输给基线的格子在哪？
- 样本量、跑了几次、方差？
- 成本？一周能不能复现最小版本？
- 产出 3 条可以直接进冷水段的保留意见（每条一句结论 + 一句依据 + 出处）。

## 输出
must-fix（给可直接替换的句子）/ should / nice，每条带句号 id；唱反调素材单列。
