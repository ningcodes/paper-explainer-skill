# brief 模板：「只听一遍」理解测试（独立 subagent）

> 用法：复制本文件，替换 `<…>`，整段发给一个**没参与写稿**的 subagent。不要转述，checklist 原文已在下面。

你不是作者，不许改原稿。

测试对象：`<口播文件路径>` 里 `## 00` 到 `## <最后一段>` 之间以 `- ` 开头的口播句。**只读口播句，从头到尾读一遍，不回看；不要读「逻辑链」「事实口径表」「> 屏幕卡」和每段的说明（那是给作者的）。** 「‖」按约 1 秒停顿处理。

两个角色各做一遍：
- **A 不懂行**：后端工程师，用过 ChatGPT，没听过 `<本期核心术语>`。
- **B 懂行**：天天用 coding agent（Claude Code / Codex 等），没读过这篇论文。

固定问题（A、B 都答）：
1. 用 3 句话复述，包括例子里每个角色手里拿着什么、改了什么。
2. 核心机制凭什么判断 / 为什么有效？
3. 标题里的「`<标题关键词>`」体现在哪？
4. 每个设计为什么要这样？
5. 在哪一句走神或听不懂（行号 + 原因：跳步 / 术语没定义 / 新概念没铺垫 / 数字挤 / 指代不清 / 太长）。
6. 会误解的地方：以为模型被训练、以为看到了分数、以为继承了上个任务的配置、以为模型自己在改自己；以及本期特有的：`<列出本期容易误解的点>`。
7. 1–10 打分。

输出：A、B 各自的 3 句复述、逐条回答、走神行号 + 原因、误解风险、分数；最后列 **must-fix（给可直接替换的句子）** 和 should-fix。**门槛：A ≥ 8 分才进入配音。**
