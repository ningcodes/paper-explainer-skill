# 论文 → 讲解视频

目标观众：有技术背景、但没读过这篇论文的人。看完要能说清：它改的是什么、为什么有效、我们能学到什么，并且能用一个具体例子复述它在干什么。公式不推导，脉络讲清楚。

成片规格：横屏 1920×1080，30fps，H.264 + AAC，**时长 6–8 分钟**，说清楚优先（约 10 分钟内都可以接受）。结尾署名、关注语是配置项（工程目录 `film.json` 的 `outro`），不写死。

本 skill 和仓库里的代码配套：`engine/`（画布外壳、实体纸、风格卡 ④、WebCodecs 渲染页、拼接混音、配音对齐、音乐音效），`examples/demo`（25 秒最小示例），`examples/always-on`（一期完整示例）。接口文档：`engine/README.md`。

## 一、硬规则（每条都来自返工，冲突时以这里为准）

1. **开工前加载本 skill 全文，派给 subagent 的 brief 里贴 checklist 原文，不凭记忆转述。** 写稿、审稿类 brief 还要贴 `references/voiceover-selfcheck.md` 全文。brief 第一行写本 skill 路径，要求先读全文。
2. **顺序不能反**：逻辑链 → 锁口播 → 分镜（镜头规划表）→ 配音 → 粗剪看流程 → 特效 / 美术精修 → 封面最后。口播没锁不做画面；分镜和稿没锁不生成配音以外的任何素材（如可选的头像）。先定风格后改内容 = 返工。
3. **写的人不验收。** 口播交审前要过独立的「只听一遍」盲测和事实核查；成片给作者看之前，必须由**没参与制作**的 agent 看完整动态片、对照 `references/review-checklist.md` 审片，审片报告一起交。
4. **渲染只走一条路**：本机 Chrome 页面内逐帧 `render(t)` + WebCodecs 硬件编码（`engine/common/shell-wc.html`）。brief 里只写这一条，不给「headless 逐帧截图 → ffmpeg」的退路。**开渲前先测 10 秒的 ms/帧和 WebGL renderer**；renderer 是 SwiftShader / llvmpipe 等软件渲染就停下报告，不换别的渲染方式。合成禁用 geq。渲染放后台 agent、独立段并行，主会话保持能随时对话。
5. **配音**：任意 TTS 出 wav → `engine/voice/align.py` 对齐。读错的句子单句重生成，不手改时间。
6. **第 0 帧就有内容，前 20–30 秒最重要。** 钩子直接：权威名字 + 最反直觉的结果 + 观众的困惑（或「一次讲完 X」），不玩悬念。
7. **长度跟着讲清楚走**，约 10 分钟内可接受；句间停顿要紧（见第 10 节）。
8. **画面**：可读性第一，暖白 / 米白编辑风；默认风格卡 ④ 报刊（已发布片在用）。喜欢连续运镜、缩放进论文页、软合成音乐床。不用 3Blue1Brown 式深色底做整片底色，也不用 Swiss 网格海报风；不做 PPT 式硬切静态卡。
9. **出镜可选**：主画面是内容。要放作者形象时只放右下角小窗、只在开头 / 章节 / 结尾出现，不要大脸；口播不原样做成大字。
10. **结尾**：讨论问题（和本期核心机制相关、一两句能答）→ 署名 + 关注语（`film.json` 的 `outro`）；不预告下集。
11. **文案**：专业精炼、有推理过程、emoji 少；不用「不是……而是……」；不写没发生的亲测；官方 claim、实测、推断分开说。口播分段给作者审。逐句自查清单见 `references/voiceover-selfcheck.md`（优先于本文件里任何旧写法）。
12. **基于已验证的做法做方案，不自己发明新格式。** 新镜头先在 `examples/` 里找同类写法。

**作者必须亲自做的环节（agent 到这里停下，说清要作者做什么，等确认）**：审逻辑链和口播（第 7 节）、生成配音 wav（第 9 节，除非作者已给出可用的 TTS 方式）、看镜头规划表（第 8 节）、看样片和成片（第 11–12 节）、发布。作者没审完，同一条片不往下一阶段走（别的片可以继续）。

**省 token**：每个交审版本最多 1 轮事实核查、1 轮盲测；小问题攒着和作者意见一起改。查找、整理文件用小模型；写稿、事实判断、审片用强模型。大段内容写文件，只回传路径和结论。

## 二、流程总览

0. 选题筛查：论文概览 + 你发布平台上的同题热度；硬门槛：论文里有一个完整的 case study
1. 精读 → 论文卡（`references/paper-card.md`）
2. 找钩子
3. 三问提纲 + 贯穿例子 + **观众问题链**（`references/question-chain.md`）
4. 写口播（第 4 节 + `references/voiceover-selfcheck.md`）
5. 「只听一遍」盲测（两个角色，subagent，`references/listen-test-brief.md`）→ 补稿
6. 独立事实核查 + 唱反调（subagent，并行，`references/factcheck-brief.md`）→ 改稿后**再测一次理解**
7. **作者逐段审口播**（逻辑链一页 + 分段口播，等确认）
8. 分镜：选风格卡 + **镜头规划表**（`references/shot-plan.md`）+ 顶部栏目进度条 →（**作者看镜头规划表**）
9. 配音（任意 TTS）
10. 对齐、音轨（人声 + 音乐床 + 音效）
11. 公用件 → 按章并行写 scene.js → 样片 → 独立审片 → 全片 → 逐章美术精修 → 再审 → .1 修订
12. 抽帧自检 → 交付；作者看完提的问题先复盘再动手改

### 多来源「一次讲完」也用本 skill
综述 / 多篇论文串讲同样走 0–12 步。不加载本 skill 的后果：句子塞满「机构 + 年份 + 数字」一口气念完、章节各讲各的、没有真实论文页、没动效没音乐、没做理解测试，整片返工。适配：
- 用**一个贯穿例子 + 一张母图**串全片；每章用同一套词重走母图。母图优先用论文里现成的分类，正文按这个分类分章讲，不自造框架。
- 每章只讲一个主故事、一个主数字；其余数字放屏幕来源卡，口播只说「X 发现」。
- 章节递进（由浅到深 / 流水线顺序），最后一章回扣开头钩子。
- 机构、年份不进口播长句；一句一个信息。
- 综述的权威来自「论文 + 大厂开源代码」；钩子只留一个主语。

## 0. 选题筛查

- 候选多时先看论文的 AI 概览（如 alphaXiv），只用于决定要不要精读，不作为事实来源。
- **在你要发布的平台上查同题热度**：有没有人讲透、讲透的那几条反响如何。学术热度（点赞、引用、论文数）不等于平台热度；平台上火的通常是「概念讲清楚」「一篇就够了」和人名 / 公司。没有证据不说「最近很火」。
- **硬门槛：论文里要有一个完整的 case study**（输入 → 每层做了什么 → 前后分数），能撑起「走一遍」。没有就慎选。
- 选题先定四件事：读者的问题、我们的主张、证据、交付（看完能带走什么）。

## 1. 精读：论文卡

- 拿全文：`https://arxiv.org/pdf/<id>`；能拿就同时拿 TeX 源码（`/src/<id>`，数字、图注更准，原图可直接用）；PDF 下载失败先读 `arxiv.org/html/<id>`。只下载你有权使用的材料，记下许可（CC BY 等）。
- PDF：`pdftoppm -r 150` 渲染全部页面看内容；**画面用的页面和局部用 300dpi，要钻进去的图用 720dpi 矢量渲染**（镜头要推进 2–3 倍，150dpi 或视频截帧会糊）。词框（给荧光笔定位）用 `pdftotext -bbox`；它在某些 poppler 版本会崩，改用 PyMuPDF（见 `examples/demo/get-paper.sh`，记得 NFKC 归一化，否则 ﬁ 连字会找不到句子）。网页原文用 `engine/tools/capture.mjs`（3× 截图 + 短语词框）。
- 正文、附录、图注全部读。附录、消融、失败案例、局限必须单独过一遍。**附录里的提示词、判定规则、伪代码必须读**：核心机制「凭什么判断」经常只写在这里。
- 论文卡按 `references/paper-card.md` 的 12 项写。单篇拆解先抓原文自己的核心图和结构，不套自己的框架。

## 2–3. 钩子、三问、贯穿例子、观众问题链

**钩子**（每句 ≤3 秒，一句只放一个信息）：
1. 权威名字压短放最前（「Google 新论文：」）。
2. 紧跟这篇**最独特、最反直觉**的那一点，场景说人话（「帮制片人把排期、人员、预算几份表对上账，得分从 43 涨到 78」）；单个案例保留「一个真实的……」这类限定，不能说成平均。
3. 可以用一句短的反转收尾（「模型一行权重都没动。」）。
4. 再给全名和机构，加一句预告（「接下来我们一起拆解它的完整架构」）。
- 不要把多个带同一个数字的量串在一句（「8B」「七十分之一」「十二点八万」会听岔）。
- 钩子里不要让观众先懂一个专有名词才能听懂：先用大白话讲事件，英文原句只放屏幕；观众不熟的术语可以出现，下一段立刻定义。
- 钩子里的比较对象要核实，限定条件写进去；**钩子和标题里的每个关键词，正文都要有一段正面回答**（说了「自进化」，就要有「这算自进化吗？体现在哪？」一段）。
- **第 0 帧就是满屏的主标题或最反直觉的画面**（132px 宋体，已在位，不从空白上推）；关键数字等口播念到时第一次出现并做成那一段的主角（≥200px），不在开头闪一下。

**三问篇幅**：改的是什么（层级）｜为什么能起作用（作者思路 + 机制 + 为什么不会失效，占一半以上）｜我们能学到什么。

**贯穿例子**：选一个论文自带的例子，覆盖每一层，所有机制都回到它。

**观众问题链（写稿前必做）**：按段写「观众听到这里会问什么 → 下一句怎么答」，模板和必覆盖项见 `references/question-chain.md`。问题链和逻辑链一起交作者审。必有冷水段。

## 4. 口播

**结构**：钩子 → 问题（前人点名一个具体工作）→ 如果你是作者 → 一句话本质 → 架构（按论文分组讲）→ 用论文例子走一轮（分步，每步带「为什么」）→ **总结卡（一句话串起所有步骤）** → **标题概念答疑** → 结果（问题 → 答案）→ 冷水（编号）→ 我们能学到什么 → 结尾（讨论问题 → 署名 + 关注语）。

**讲清楚的硬规则**
- **只给名字不算解释。** 每个术语 / 机制第一次出现时，用一句话给操作定义：谁、看什么、怎么判定。翻译论文术语不等于解释。
- **不跳步。** 动作之间要有因果衔接（「看到这两个毛病 → 动手改 Harness 的文件」）。
- **先具体后抽象。** 先说改了哪几个文件、写了什么，再说它属于哪一类、叫什么。
- **新概念先铺垫再使用。** 不能让「候选」「盲选」这类词第一次出现就在冷水段。
- **证据放在步骤讲完之后**，不在步骤中间插数字；讲对照实验先说对照组怎么做的，再说结果。
- **角色交代清楚**：多个模型时明说「这里有两个模型：干活的是 X，改 Harness 的是 Y」；说清权重变不变、有没有强化学习。
- **benchmark 名第一次出现先交代是什么**；单位全片统一（「分」不混「百分点」）；「它」不能有歧义。
- 画面上只用口播里出现过的叫法。

**风格**
- 观众熟悉的英文术语（Harness、agent、diff）直接用，全片一个叫法，不另起中文译名。用行业原词（RL 环境、轨迹、verifier），不自造比喻。
- 场景说人话；任务、benchmark 名先翻成一句大白话。
- 如果你是作者：问完「你会怎么想？」留 1 秒停顿（画面出「？」），再说「我猜……」。推测必须说「我猜」。
- 一句话本质：能被复述，后面跟一句补充；不写口号式短句（见自查清单）。
- 长列表按论文自己的分组讲，分组以论文原表为准。直接讲论文，不硬往观众的工具上靠。
- 走一轮：分「第一步……第二步……」，每步说清谁拿着什么、做了什么，补一句「为什么」。精选案例要说明「这是论文挑出来展示的，平均没这么大」。
- 每个机制按「原来怎么做 → 有什么问题 → 改成什么 → 为什么更好」讲。
- 技术机制配最小的前后代码对比；有原文就用原文（标「原文摘录 · 有删节」），没有就写伪代码标「示意」。
- 类比只作辅助，放在例子之后。讲「试过但没留下的」方案。删信息前先问：删掉后观众会不会理解错？
- 结果段：每个数字回答一个问题，不念成绩单；几个数不要挤在一句里。同一个「最多 / 最大」来自不同对比时点明范围。
- 冷水段：「有三个保留意见。第一……」编号完整；素材来自唱反调 subagent；引用有利数字时把反方向的也说出来。
- 结尾不说教：「那我们能从中学到什么？」「我自己最大的收获是……」；不用「你能带走」这类命令句。
- 口语、短句；字幕用阿拉伯数字。
- **交审前逐句过 `references/voiceover-selfcheck.md`。**

**字数与节奏**：整体约 5.8 字/秒（汉字、英文词、数字各算 1）；6–8 分钟 ≈ 2000–2700 字。不靠提速，砍碎停顿：同一段里句子连成一口气，只在抛问题、反转、关键数字前留整拍；稿子里用「‖」标出整拍停顿（每章 3–5 处）。目标停顿占比 10–12%、平均 5–6 秒停一次。

**口播文件格式**（引擎直接读）：段标题 `## 00 · 段名`，念的句子一行一个、以 `- ` 开头；「> 屏幕卡」和说明文字不念。句 id = `s<段>-<序号>`。

## 5–6. 盲测 + 事实核查 + 唱反调（独立 subagent，同时跑）

- **只听一遍盲测**：两个角色（A 不懂行、B 懂行），固定问题、误解清单、打分。**门槛：A ≥ 8 分才进入配音。** brief 模板 `references/listen-test-brief.md`。盲读提到的问题要逐条处理，不能只补一句了事。
- **事实核查**：口播 + 论文，逐条核数字、归因强度、限定条件、比较对象、「推测」是否标明、分组是否和论文原表一致；输出 must-fix（可直接替换的句子）。
- **唱反调**：只给论文，站审稿人立场：最脆弱假设、对比是否公平、输给基线的格子、样本量、反例、一周复现；产出冷水段素材。核查和唱反调 brief 模板 `references/factcheck-brief.md`。
- **每改一轮稿（尤其核查后加了数字和限定条件），都重新跑盲测 + 核查改动句。** 准确和好懂要一起过。门槛按已发布稿校准。

## 7. 作者审口播（停下等确认）

- 先给一页逻辑链：每段一行「观众的问题 → 这段的回答」。
- 不贴一整块文字：按段分块，小标题 + 一句说明 + 口播一句一行；关键结论加粗。
- 逐段 review，每次 1–3 段，写「现在 → 问题 → 改后」，问能直接回答的是 / 否问题，用大白话带上背景；有合理默认就按默认做，说一句做了什么。
- 作者的偏好记下来，结束后更新本 skill。确认后才配音和制作。

## 8. 分镜：风格卡、镜头规划表、进度条

### 风格卡
画面 = **骨架**（结构、运镜、钻进论文、大画布、转场时机，全片固定）+ **风格卡**（色板、字体、材质、标志动作、固定元素样式）。换风格只换卡。一支片子只用一张卡，系列内保持同一张卡。节拍跟口播走，每个镜头的构图按卡重新设计。

**卡 ④ 报刊数据新闻（默认，`engine/common/style.js` 已实现）**
- 色板：纸 #FFF1E5｜墨 #33302E｜次要 #66605C｜细线 #CCC1B7｜**酒红 #990F3D = 改进后 / 关键数字 / 我们的标注**｜**牛津蓝 #0F5499 = 基线 / 原版**｜青 #0D7680 = 对上、连线、✓｜灰 #B9AFA6 = 被拒 / 中性｜麦色面板 #F2DFCE。
- 字体：中文标题 Noto Serif SC Black（钩子 132px、章节 / 镜头主标题 92px、卡片 56–64px，行距 1.1）；正文、标签 Noto Sans SC；数字 Inter 800 + tnum；栏目标签（kicker）Bold 28–30px、上压一条 56×5 酒红短线。字体由 `style-cards/editorial/get-fonts.sh` 下载（OFL）。
- 版式：kicker + 大标题 + 导语 + 图；左边距 120px、严格栏格；1px 细线和 4px 粗线分层；图表只画横向网格线，标签直接贴在线和点上，不用图例；注释 = 细引线 + 一句短说明；每屏左下角灰色来源行（≥26px，chrome.js 统一画）。
- 标志动作：标题逐行遮罩上推（easeOutQuart 0.55s，`ED.maskLine`）；导语从左擦出（`wipeText`）；细线从左长出（`growLine`）；外框顺时针描边（`strokeCW`）；折线从左画到右、数字同步滚动；关键短语酒红下划线扫出（`underlineSweep`）；图表镜头缓推 3–4%。**不弹跳、不发光。**
- 转场：章节之间整页横滑翻报纸（0.6s，chrome.js 统一画）；章节内连续变形 / 大画布。
- 固定元素：顶部报纸栏目导航进度条、麦色字幕条（宋体 Bold 44px）、来源行——全部由 `engine/common/chrome.js` 画，章节不自己做。
- 缺点：偏冷、字多层级多，手机上 28px 注释仍偏小，能删就删。

**其他卡（仓库未附实现，按需自己写 style.js）**：② 手绘白板（Excalidraw 风，适合架构拆解）；① 数学动画（3Blue1Brown 风，适合公式推导；硬规则 8 不推荐整片深色底，真要用时深色底上的 PDF 白页压亮度加暗角）；⑤ 暗色开发者（适合工程实操）；③ 新粗野主义（适合短钩子，长片会累）；A 暖白讲解（底 #FAFAF7、焦橙 #D4552A = 改进、石板蓝 #3E6A8A 虚线 = 基线）。换卡时：动法不变，只改缓动性格（④ 不回弹）和章节转场外观；颜色语义固定：改进后 = 卡的强调色，基线 = 冷色，被拒 = 灰。

**高密度段落规则（所有卡）**
1. 一屏一个主角：讲谁就让谁占约 65% 宽、镜头推近 1.3–1.5 倍；换主角时上一个收成顶部摘要细条；只在点明关系的那句拉远看全局 1–2 秒。
2. 文字限额：字幕之外每屏 ≤ 约 25 个中文字、≤4 个视觉块；口播说过的话不再写成标签；一个元素最多一个标签。
3. 不用中英双标签；所有要读的字 ≥28px，来源行可 26px。
4. 看不清的论文小剪报不放：要引用就全尺寸钻进去看清 ≥1.5s，用完只留来源行或小角标。
5. 占位克制：下一栏只留一条细线 + 小栏头，不铺大片灰色骨架。
6. 顶部只留一条导航：本章步骤做成进度条里的子刻度，不再单独占一行。

**所有卡通用的分镜规则**
- 核心节拍：原文页 → 黄色荧光笔 rgba(250,199,117,0.7) 跟口播从左往右涂（配马克笔声）→ **原文清晰停留 ≥3 秒（不算进出场和推拉）**；图表重绘前先展示原图并圈出要讲的点。
- **荧光笔分两种**：原文上划重点 = 黄色（所有卡一样）；我们的标注（引线、圈、下划线）= 卡的强调色（④ 酒红）。观众一眼分清哪个是原文、哪个是解读。
- 固定镜头：走一遍镜｜代码对照镜｜层级表镜｜作者思路镜（标「推测」）｜对照实验镜（实验组 vs 对照组怎么做）｜总结卡。
- 字幕底板不透明度 ≥0.97，一行 ≤22 字，与口播逐字一致。
- **字号：要让人读的字 ≥28px**；承载信息的字用墨色，灰字只给元数据。
- **不留空屏**：内容铺满约 70%；任何时刻（包括变形和换镜的中间帧）半屏空着不超过 2 秒；落地帧就要有主角。
- **画面语义别误导**：竖排箭头链会被读成数据流；不流向下一个角色的东西放旁边、虚线框并标注。
- 示意图标「示意」；图表按比例、轴有标签；论文 logo 遮掉，机构名只用文字。
- 不准随机噪点填充（Math.random 的灰度格、条码、骨架条）；示意图用 3–4 档平滑色阶。
- 标题不准新旧叠在一起（先出后进）；新画面出现前旧画面完全退场，不留残影。
- 含文字的层不靠 `scale()>1` 放大位图，改布局尺寸重画。
- 3D 一律用 Three.js 打光（圆角盒子、哑光材质、半球光 + 主光 + 补光、烘焙接触阴影，2× 渲染再缩小）；禁止 CSS 3D。

### 安全区（分镜阶段就按这个排版）
- y 0–64：只给进度条；片内元素上边界 ≥ y80，常规内容放在 **y 136–930、左右 96px** 内。
- y 900–940：来源行；y 952–1040：字幕条。图表数字、标签不进这两条。
- 可选头像：右下角约 x>1660、y>840；要读的内容放在 x<1640、y<940。
- 别事后把进度条 / 头像叠到成片上（只能把正文缩小，字幕跟着变小）。

### 运镜与转场（三种手法按内容分工）
禁止「淡出到空白页再从零搭」和整屏交叉溶解（像翻 PPT）。

| 内容 | 手法 | 做法 |
|---|---|---|
| 大部分讲解：概念、背景、一句话本质、结果、冷水 | **连续变形**（3Blue1Brown 式） | 下一镜的元素从上一镜里长出来：标签飞到中间变成主图形，标题词缩小并入公式，子元素在口播点名时从父元素里弹出，? 变灯泡、问题卡翻成冷水卡。每个进场元素都要有来处 |
| 引用论文原文、原图 | **钻进论文**（实体纸） | 论文是一张有阴影、约 1.5–2° 倾斜的真纸（PDF 真页面，不用灰条占位），平时缩在角落；要引用时滑回、翻页（0.8s，画出纸背）、推进 2–3 倍到那句或那块图，荧光笔划过；讲图时把图里那一块「浮起」飞出变成重画的动画卡。浮起的截图停在旁边不盖目标卡，用完收进角落小地图。推近不超过截图分辨率 |
| 有先后步骤的段落（走一轮、流程） | **大画布运镜**（Kurzgesagt 式） | 几步从左到右排在同一张大画布上；镜头在步骤间平移（0.5–0.9s easeInOutCubic + whoosh）；角落放论文小地图。下一站的骨架提前铺好，平移途中就能看到目的地；画外被切一半的邻卡压暗。一期只用 1–2 段，走完拉远看全图再收成总结链 |

- 全片骨架：连续变形打底 → 每次提到论文就钻进去 → 讲步骤时走大画布 → 大段落之间用 ≤0.6s 的章节转场，只用 5–6 次。
- 动效语法：进场 ease-out（④ 不回弹），子元素错开 60–120ms；镜头 easeInOutCubic；同一个物体跨镜头保持同一个元素（插值位置 / 缩放），不复制一个新的淡入；卡片缩放时内容跟着缩，不先清空再缩。
- 运动模糊：12–16 份等权采样，拖尾 ≤ 单帧位移的一半且 ≤40px；推拉时不加方向模糊；甩镜整屏模糊 ≤0.35s。
- **先出镜头规划表**（`references/shot-plan.md`）：每段写用哪种手法、上一镜留下什么、下一镜从哪个元素长出来、原文出处、锚词。作者看过再做画面。

### 顶部栏目进度条
- 按口播段落分 6–8 栏，**屏幕上用两字报刊栏目名**（导读 / 背景 / 思路 / 拆解 / 结果 / 存疑 / 启示……）；「钩子」「冷水」是内部叫法，不上屏。
- 配置在工程目录 `film.json` 的 `nav`：`[{ "n": "01", "name": "导读", "sections": ["00"] }, ...]`；起止时间取自 timeline.json。当前栏酒红宋体，已播进度酒红线，每栏最后 2 秒下一栏脉动预告。实现：`engine/common/chrome.js`。

### 头像（可选）
默认不放。要放时用你自己有权使用的形象，自备一条透明背景的头像轨，在合成最后一层叠到右下角安全区；全片常驻或只在开头 / 章节 / 结尾出现；**镜头推近论文（≥1.4 倍，或原文会落到右下角）时整个滑出画面，拉远后滑回**，各 0.35s，不要半透明。分镜时就按安全区排版。

## 9. 配音（任意 TTS）

- 用任何能出 wav / mp3 的 TTS（商用网页、API、本地模型都行），按段生成（每批 ≤450 字左右，太长容易吞字）。数字、版本号写成中文读法（四十三点一、Opus 四点八）；英文术语保留；字幕用阿拉伯数字（chapter.json 的 numfix）。
- 每批先做语音识别核对首尾词和英文专名（`engine/voice/align.py asr`），读错的句子单句重生成，写进 voice.json 的 `overrides`。
- 一种已验证的做法（示例）：某商用 TTS 网页，选一个技术解说风格的音色，1x 语速；每段「粘稿 → 自动加情绪标签 → 生成 → 下载第 1 条」；用浏览器自动化时开自己的新标签，不碰用户正在看的标签。音色和账号自备，不随仓库分发。
- 交付前逐段转写核对原声首尾词；淡出 ≤2 帧。

## 10. 对齐与音轨

- `uv run --with numpy python engine/voice/align.py voice.json`：识别结果按字对齐口播 → 句边界吸附静音 → 每句去首尾静音、句内长停顿压到 ≤0.30s、atempo 1.05、8ms 淡入淡出 → 拼接输出 `voice/voice.wav`、`timeline.json`、`clauses.json`。
- 停顿参数（最新已发布片）：片头 0.3s、句间 0.35s、段间 0.7s、片尾 2.5s；问句、「‖」处、关键数字前可加到 0.8–1.0s。
- **timeline.json 是全片唯一时间源**：进度条、字幕、锚词、音效 cue 都从它来。补句子只需新增片段、重跑 align。没配音时用 `engine/tools/mk_dummy_timeline.py` 出占位时间轴先做画面。
- **背景音乐**（`engine/audio/audiolib.py music`）：numpy 合成，不用有版权素材。暖 pad + 柔和琶音 + 低音，F 大调 Fmaj7–Dm7–Bbmaj7–C7，84 BPM；约 −28 LUFS；人声出现时 ducking 约 7 dB（起音 60ms / 释放 450ms）；片头片尾淡入淡出。
- **音效**（`sfx`，比人声低约 19 dB；24 dB 在手机上听不到）：镜头移动 / 章节转场 = whoosh；荧光笔 = marker；卡片 / 标签 / ✓✗ = pop（对齐到元素真正进场的那一帧）；数字滚动 = tick；纸张浮起 / 翻页 = paper。没有画面运动的时刻不放 whoosh。时间点由 scene 里 `data.cue()` 登记，和 render(t) 同一时间源。
- **混音**（`mix`）：两遍 loudnorm I=-16:TP=-1.8:LRA=11 → AAC 192k；编码后实测真峰值 ≤ −1.5 dBTP。
- 交付前用耳机和手机外放各听一遍（只按测量值调不算数；agent 听不了，就请作者听并指出口播最密的时间段）。

## 11. 制作与渲染

**公用件先做好再派活**（接口文档 `engine/README.md`）
- `timeline.json` / `clauses.json`：全片时间；章节时间 = 本章 section 起止，章内用局部秒。
- `film.json`：章节顺序、进度条栏目、结尾署名。
- `engine/common/chrome.js`：进度条、字幕、来源行、章首翻报纸。章节只画 `renderContent`，**不自己做固定元素**，这样拼起来只有一套 UI。
- 章节 brief：风格卡全文 + 高密度规则 + 接口 + 事实规则 + 预算；**一开始就写进「版面铺满约 70%、任何一帧（包括变形和换镜的中间帧）都不能近空屏、镜头主标题 92px、不用灰条占位」**。
- 母图：全片共用的母图代码写成规格文件（如 `examples/always-on/MOTHER.md`），各章原样复制。

**按章并行**：每章一个制作 agent，主控只做公用件、统一渲染和拼接。
- scene.js 的 `renderContent(ctx, t, data)` 必须是 t 的纯函数：无 CSS 动画、无计时器、随机数用种子 PRNG。**切点只能从锚词算**（`data.A(句id, 子串)`），不手写秒数。
- 章节衔接：每章 t=0 必须已是完整版面、最后 0.5s 落定不动；`engine/tools/prep_render.mjs` 导出上一章 nochrome 末帧当下一章翻页底图（prev.png）。第一章可以实现 `renderPrev` 自己画「上一页」。
- 超长章（>90s）拆两个 agent，用一次甩镜交接：交接帧上的元素坐标、画布坐标、末速写死在 brief 里。
- 改了公用件要广播给所有章节 agent，已渲的章补渲受影响的帧；拿不准就全章重渲。
- 制作 agent 自检只抽静帧（headless 打开 shell 页 `seek(t)` 截图，每轮 ≤10 帧）；**成片只走 WebCodecs**。

**渲染（唯一路径）**
1. `node engine/tools/serve.mjs 8771`（只监听 127.0.0.1）。
2. 本机 Chrome 开新标签：`http://127.0.0.1:8771/engine/common/shell-wc.html?ch=<章节目录>`。
3. 控制台 `await probe()`：看 `webglRenderer`（应是真 GPU，如 Apple M 系列 / Metal、NVIDIA、AMD）和 `prefer-hardware` 是否支持；`software: true` 就停下报告。
4. `startRender({ to: 10, download: false })` 实测 10 秒，看 `__prog.msPerFrame`（GPU 上一般 5–15 ms/帧）。
5. `startRender({ name: 'chNN.mp4' })` → 轮询 `__prog.state === 'done'` → 浏览器下载。**每个标签只下载一次**（第二次会被 Chrome 静默拦截），一个输出一个新标签，渲完关。
6. 下载后 cp（不要 mv）到 `<章>/build/video.mp4`，`ffprobe -count_frames` 核帧数 = `ceil(T×30)`。
7. `node engine/common/assemble.mjs --project <工程目录>`：逐帧对齐 concat、音乐音效、混音、封装，另出 <30MB 轻量版。混音不用 -shortest，音画差 < 1 帧。

**顺序：样片 → 独立审片 → 全片 → 美术精修 → 再审 → .1 修订**
1. 先出两段完整合成的样片：A = 钩子 + 第一次钻进论文（约 30 秒）；B = 进入大画布的头一两站（约 40 秒）。给作者看效果、听音量，同时交给审片 agent。
2. 审片 agent 独立于制作（只看成片 + 本 skill + 论文卡），按 `references/review-checklist.md` 逐条查，输出 must-fix / should / nice，带时间码和具体改法。
3. must-fix 全片统一改，不只改样片范围。
4. **逐章美术精修**：内容和时间轴锁死后，每章交给只管美术的 agent（不改口播、镜头顺序、数字），每个镜头抽 3 帧（进场中 / 落定 / 离场前），像海报一样能单独截图才算过；查字体四级层级、主角够大（关键数字 ≥200px）、标志动作用上了、颜色语义没乱、对齐栏格、没有「默认灰框 + 小字」的 PPT 卡片。发现内容问题记到 review，回给制作方。
5. 全片再审一轮，修完出 .1 版；有一轮审片之前不发「最终版」。

## 12. 自检与交付

- 按 `references/review-checklist.md`：每镜中点和末尾抽帧 + **每个转场按 6fps 展开**（不许出现空白页过渡帧）+ 首尾 + 原文页出现后 1 秒；字幕逐字对稿；响度实测。
- 交付：原版 mp4 + <30MB 轻量版 + 联系表 + 关键镜头 JPG；交付说明列：这版改了什么、剩下的小弱点（带时间码）、需要作者听的时间段。
- 成片后作者提的问题：先复盘（问题类型、为什么没提前发现、怎么避免），确认后再改；只重录受影响的配音段、局部重渲。新的教训写进 `references/pitfalls.md`。
- **封面最后做**：直白标题（「N 分钟读懂 X」）+ 机构名写全 + 论文第 1 页实体剪报 + 关键数字块；要更亮眼时给 2–3 个**版式**不同的方向，不只换配色。

## 常见坑

全集（带来源）见 `references/pitfalls.md`。最常犯的：
- 照摘要顺序讲 → 成绩单；只有类比没有例子 → 抽象；用名词代替解释 → 「没有标准答案怎么判断」。
- 标题承诺没兑现；对照实验只报结果不说对照组怎么做；删掉「谁在干活」→ 以为模型在自己改自己。
- 核查后只加准确度、没重测理解 → 变密变难懂。
- 每镜淡到空白页再重搭 → 像 PPT；论文原文是一小段字浮在空白页上 → 没有实体感；用视频截帧或灰条占位当论文素材 → 推近发糊。
- 各章 agent 自己做进度条 / 字幕 → 几套 UI；简报没写死「铺满 70%、中间帧不空」→ 第一轮各章普遍稀。
- 改了代码只重渲一部分分段 → 成片混着旧画面。
