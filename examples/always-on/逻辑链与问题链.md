# Anthropic 如何做 Always-on Agent｜逻辑链与问题链（v1）

**主线：** 文章那张总图。一直在线的 Agent 大部分时间在睡觉；有事件来了醒一下，跑一次 run，存好状态再睡。让这个循环转起来，要五样东西：事件收件箱、定时器、记忆、权限、发件箱。

**结构照抄 Memory 那期（v15）：** 开头直接给文章和核心图 → 讲图 → 按图逐块讲 → 合起来 → 保留意见 → 回到图收五条 → 讨论问题 + 固定结尾。

**贯穿例子：** 文章自己提到的「每天一份简报」（daily newsletter，原文 schedule 的例子），配 reported.md、用户回复续会话。只在 07 段完整走一遍，标「示意」。各段机制用原文自带的例子（连发几条消息合成一次回复、过两天看看有没有回复、工单系统存指针）。

| 段 | 观众的问题 | 这段的回答 | 主图 | 主数字 |
|---|---|---|---|---|
| 00 开头 | Anthropic 发了什么？一直在线是怎么做到的？ | 11-13 官网文章；反常识：它大部分时间在睡觉，醒一下跑一小段再睡；今天讲背后五样东西 | 时间轴图（Asleep / Run） | 无 |
| 01 一次 run | always-on 和普通 Agent 差在哪？为什么现在多起来？ | 有状态 + 主动；内核还是同一个循环，差在外面那圈；一次 run 四步；模型判断力更好、长任务更便宜 | 时间轴图四步 | 78% / 40% |
| 02 事件收件箱 | 谁叫醒它？为什么不直接调用？ | 直接调用会抢跑、会丢；先落表，handler 写、worker 读；四条经验 | 收件箱图 | 无 |
| 03 定时器 | 没人叫它，它怎么主动？ | follow-up 和 schedule；scheduler 扫表，到点写进收件箱 | 定时器图 | 无 |
| 04 记忆 | 每次 run 断开，怎么接上？存什么？ | 只存查不回来的东西；四类文件，每次只加载小的那几个；dreaming 可选；上下文开销要小 | 记忆目录图 + 上下文图 | 无 |
| 05 权限 | 没人看着，它会不会乱来？ | 凭证在代理里注入；auto mode 分类器拦危险操作；要人批的先挂起，回答作为事件续上 | 总图权限块 | 无 |
| 06 发件箱 | 做完怎么告诉我？会不会刷屏？ | 三种结束方式；send 工具通常够用；发多少要评测，先少说话 | 发件箱图 | 无 |
| 07 合起来 | 五样东西怎么连成一圈？ | 总图走一遍 + 每日简报示意走一遍 | 总图 | 无 |
| 08 保留意见 | 这篇能全信吗？ | 实践指南、几乎没有实验数据；关键参数没给；权限最重要的决定仍要人批 | 无 | 无 |
| 09 结尾 | 带走什么？ | 五样东西各一句；讨论问题；固定结尾 | 总图 | 无 |

## 必答问题的落点

| 问题 | 在哪答 |
|---|---|
| 标题「always-on」体现在哪、哪里不成立 | 00、01：其实大部分时间睡着；07：一直转的是循环 |
| 谁在干活、权重变不变 | 01：内核是同一个 Agent 循环；全片不涉及训练，模型不变（01 一句交代） |
| 每个组件「凭什么 / 为什么这样设计」 | 02 直接调用的两种失败；03 收件箱只放现在能做的；04 查得回来的存指针、每次加载都要付 token；05 run 持有用户权限且无人值守；06 太吵 / 太闷 |
| 有没有对照实验 | 只有 01 一组成本对比；08 明说其余没有数据 |
| 和上周 Memory 那期的关系 | 04 一句：dreaming 在 Anthropic 11-06 记忆文章里讲过 |
